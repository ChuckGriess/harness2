Risks &amp; rollback

  • Risk: Gold curation is manual and is the real bottleneck; thin gold rewards precision over recall — mitigation: Start with 18 tasks; radar_gold.py drafts candidates from watchlist sources; track gold size per task in the report
  • Risk: Live web drift makes rollouts non-reproducible across days — mitigation: Closed past windows; the run_dir caches fetched sources and the judge grades against that cache; record the run date with results
  • Risk: Prompt injection from fetched pages steers the agent — mitigation: Narrow tool surface (no bash, no send, writes only to output/); container egress allowlist; delivery from host code only
  • Risk: Price table goes stale, so reported cost is wrong — mitigation: Dated CLAUDE_PRICES constant; Phase 0 verification; cost is labelled an estimate in report output
  • Risk: Improver-edited fetcher scripts attempt off-allowlist egress or heavy work — mitigation: Proxy allowlist + run_script timeout; validate_tree rejects non-stdlib imports in scripts/
  • Risk: Touching core/proposer.py and core/spec.py widens the review surface on a research codebase — mitigation: The changes are additive (new channel value + method); existing five regressions must stay green; channel tests added
  • Rollback: Each phase is its own commit on a feature branch (feat/ai-radar). Revert the phase commits in reverse order; nothing outside the new files changes behavior for existing benchmarks or substrates, and dependencies stays [].
